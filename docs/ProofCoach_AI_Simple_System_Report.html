Product Concept & Thesis

What Is ProofCoach AI?

ProofCoach AI is a privacy-first career preparation system designed to help students, freshers, and technical candidates bridge the gap between writing an impressive resume and defending their skills in real technical interviews.

The Core Problem

In the era of generative AI, anyone can generate a resume full of impressive-sounding keywords and metrics (e.g., "Reduced API latency by 35%"). However, candidates frequently struggle when interviewers challenge those exact claims:

The Preparation Gap: Candidates polish resume wording, but have never practiced explaining their baseline measurements, architectural trade-offs, or personal contributions under pressure.

The ProofCoach Solution

ProofCoach connects the candidate's journey into an unbroken, evidence-backed chain:

RESUME
What you write
→
PROOF
What you built
→
INTERVIEW
What you defend
→
FEEDBACK
Where you stand
→
IMPROVEMENT
What you close

Who Is It For?

🎓 Students

Translate university coursework and academic projects into defensible, commercial-grade evidence.

🚀 Freshers & New Grads

Overcome limited work history by building verified project artifacts that bypass automated parsing barriers.

💼 Early-Career Engineers

Core Engine Data Flow

What Happens Inside?

ProofCoach AI connects your documents, goals, and interview performance through an automated internal processing chain. Here is what happens behind the scenes:

1. RESUME UPLOAD
→
2. TEXT & PARSER CHECK
→
3. CLAIM DETECTION
→
4. ROLE MATCHING
5. EVIDENCE MAPPING
→
6. CLAIM INTERVIEW
→
7. EVALUATION & GAPS
→
8. ARTIFACT CREATION

Step-by-Step Flow Explanation

1
Resume Upload & In-Memory Extraction: The user selects a PDF or DOCX file. The system processes it in RAM—files are never permanently stored on a cloud server.
2
Parser Robustness Diagnostics: Software inspects reading order, contact details, dates, and warns if two-column layouts or tables may confuse automated parsers.
3
Claim Detection: The engine scans for quantified statements (e.g., "Reduced API latency by 35%") that require technical defense.
4
Role Matching & Gap Identification: Candidate skills are compared against role requirements (e.g., Backend Developer). Covered skills and missing gaps (e.g., Docker, Testing) are highlighted.
5
Targeted Adaptive Interview: The interviewer challenges the candidate on their specific claim: "What was the baseline? How did you measure it? What did you personally change?"
6
Grounded Evaluation & Feedback: The answer is evaluated for baselines, personal ownership, and trade-offs. Weak areas become prioritized learning and project tasks.

Adaptive Interview System

How the Interview Works

Instead of asking generic trivia questions, the Live Adaptive Interview interrogates the candidate directly on the achievements they claimed on their resume.

PRESENT CLAIM PROBE
→
USER ANSWERS (Voice/Text)
→
EVALUATE INDICATORS
→
ADAPTIVE NEXT QUESTION

What the System Evaluates (Observable Indicators)

ProofCoach evaluates observable communication and technical structure—never fake emotion analysis:

🎯 Relevance & Completeness

Did the candidate directly answer the question using appropriate technical vocabulary?

🏗️ Answer Structure

Did they follow a clear problem-solving flow: Problem → Approach → Contribution → Trade-offs?

👤 Personal Contribution

Did the candidate clearly separate what they personally implemented from team accomplishments?

📏 Baselines & Measurement

Did they state starting numbers (e.g., 420 ms) and specific verification tools (e.g., Postman, benchmarks)?

The 4-Way Adaptive Questioning Route

A
Strong Answer: The system progresses to harder questions covering trade-offs and scaling limits.
B
Weak Answer: Triggers a clarification question to help the candidate articulate core concepts.
C
Unsupported Claim: Triggers an evidence challenge demanding baselines and metrics.
D
Disorganized Structure: Triggers a communication follow-up to structure the response clearly.
Ethical AI Boundary: The current prototype uses deterministic, rule-based evaluation to demonstrate the concept reliably without external AI API costs. Voice features use browser speech recognition. No facial or emotion analysis is used.

Technical Architecture

What Is Happening Technically?

ProofCoach AI runs on a clean, decoupled, local-first technical architecture designed for speed, privacy, and offline reliability.

USER INTERACTION
→
REACT 19 SPA (Client)
→
FASTAPI BACKEND
→
LOCAL SQLITE DB

The Five Core Technical Pillars

⚛️ React 19 Frontend

Single Page Application built with Vite and TypeScript. Manages local state via ProofContext and uses React Flow for graph mapping and Recharts for metrics.

⚡ FastAPI Python Backend

Lightweight asynchronous service running on localhost:8000. Implements clean REST endpoints for parsing, matching, and interview evaluation.

📑 In-Memory Document Parsers

PyMuPDF and python-docx extract text and layout bounding-boxes in memory. Raw resume files are never saved permanently to disk.

🛡️ Deterministic Rule Engines

Pure Python services calculate Parser Robustness, match role requirements, and evaluate answer rubrics using transparent, reproducible heuristics.

Data Storage & Local-First Privacy

✓
Zero Cloud Telemetry: No analytics SDKs (Google Analytics, Mixpanel, Sentry) are installed or imported.
✓
Local SQLite Persistence: Profile details and interview transcripts reside exclusively on the user's computer in proofcoach.db.
✓
Zero Cloud AI Dependency: Runs reliably offline without cloud AI API keys. An optional Ollama adapter is supported for local LLMs.
